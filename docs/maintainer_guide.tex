\section{Maintainer's Guide}
\label{app:maintainer-guide}

This appendix is addressed to the person responsible for keeping this system
operational over time. No prior knowledge of machine learning is assumed.
The minimum required computing resource is a free Google Colab account for
running inference. Retraining the models requires dedicated GPU hardware;
the compute requirements for that case are described separately in
Section~\ref{sec:mg-retrain}.

% ============================================================
\subsection{What This System Does}
\label{sec:mg-overview}
% ============================================================

The system classifies a photograph of a bug bite into one of five categories:
ant bite, bed bug bite, mosquito bite, spider bite, or tick/flea bite.
It does this by running the photograph through an ensemble of three neural
network models that were trained on labelled bug-bite images. The system also
produces visual explanations showing which regions of the image most influenced
the classification decision.

The inference interface is a single Jupyter notebook,
\texttt{Stacked\_Model\_Colab.ipynb}, which is designed to run on Google Colab.
No local installation is required.

% ============================================================
\subsection{Accessing Data and Model Weights}
\label{sec:mg-data}
% ============================================================

The trained model weights are not stored directly in the repository because of
their size. They must be obtained separately and placed in Google Drive before
inference can be run.

\subsubsection{Obtaining the Weights}

Contact \textbf{ishay.yulzary@gmail.com} to request access to the weights
archive. You will receive the file \texttt{project\_book\_results.tar}.
Place this file anywhere in your Google Drive, for example:

\begin{lstlisting}
MyDrive/Capstone/project_book_results.tar
\end{lstlisting}

The notebook extracts the archive automatically on first run. If you place
the file in a different Drive location, you must update the
\texttt{PROJECT\_ROOT} variable directly inside the corresponding cell in
\texttt{Stacked\_Model\_Colab.ipynb} to match your chosen path. Changing
it in a separate cell is not sufficient, as all subsequent cells reference
the variable by name.

\subsubsection{Obtaining the Datasets}

Two datasets were used during training:

\begin{description}
    \item[Bug-bite dataset] Included in the repository under
          \texttt{Bug-Data/Multiclass\_Bug\_data/}. Contact
          \texttt{ishay.yulzary@gmail.com} for the full curated version
          used in training.

    \item[Cyclone dataset] Required only if retraining from scratch.
          It can be downloaded automatically using the provided fetch script
          (see Section~\ref{sec:mg-retrain-data}), or obtained from the
          authors via the contact address above.
\end{description}

\subsection{Running Inference}
\label{sec:mg-inference}
% ============================================================

Inference is performed through the notebook
\texttt{Stacked\_Model\_Colab.ipynb} on Google Colab.
Follow the steps below in order. Each step corresponds to a numbered cell
group in the notebook.

\subsubsection{Step 1: Open the Notebook in Colab}

\begin{enumerate}
    \item Go to \url{https://colab.research.google.com}.
    \item Select \textbf{File} $\rightarrow$ \textbf{Open notebook}
          $\rightarrow$ \textbf{GitHub}.
    \item Paste the repository URL and select
          \texttt{Stacked\_Model\_Colab.ipynb}.

    \noindent Alternatively, upload the notebook file directly via
    \textbf{File} $\rightarrow$ \textbf{Upload notebook}.
\end{enumerate}

\subsubsection{Step 2: Install Dependencies}

Run \textbf{Section 1} of the notebook. This installs \texttt{p7zip-full},
\texttt{timm}, and \texttt{lime}. This step takes approximately one minute
and only needs to run once per Colab session.

\subsubsection{Step 3: Mount Google Drive}

Run \textbf{Section 2}. Colab will prompt you to authorise access to your
Google account. After authorisation, verify that the output reads:

\begin{lstlisting}
PROJECT_ROOT exists: True
Archive exists:      True
\end{lstlisting}

If either line reads \texttt{False}, see
Section~\ref{sec:mg-troubleshoot} for remediation steps.

\paragraph{Using a different Drive path.}
The notebook defaults to \texttt{MyDrive/Capstone} as the project root.
If your weights archive is stored at a different location, you must update
the \texttt{PROJECT\_ROOT} variable directly in the notebook source before
running Section 2. In Colab, open the cell containing:
\begin{lstlisting}[language=Python]
PROJECT_ROOT = '/content/drive/MyDrive/Capstone'
\end{lstlisting}
and change the path to match your Drive folder structure. This change must
be made in the cell itself, not just in a separate cell, because other
cells reference \texttt{PROJECT\_ROOT} by name.

\subsubsection{Step 4: Extract Model Weights}

Run \textbf{Section 3}. The notebook extracts \texttt{project\_book\_results.tar}
into the Drive folder. On first run this takes 2--5 minutes depending on
archive size. On subsequent runs the notebook detects the existing extraction
and skips this step immediately.

\subsubsection{Step 5: Load Models}

Run \textbf{Section 4} (imports) and \textbf{Section 5} (model loading).
Six models are loaded: three trained with the Control pipeline and three
trained with the TC pipeline. Successful loading produces the output:

\begin{lstlisting}
All models loaded.
\end{lstlisting}

\subsubsection{Step 6: Run Inference on an Image}

In \textbf{Section 7}, set the variable \texttt{IMG\_PATH} to the path of
the image you wish to classify. The image must be accessible from within
Colab, either via Google Drive or via a direct upload.

\paragraph{Option A: Image on Google Drive.}
Place the image in your Drive and set:
\begin{lstlisting}[language=Python]
IMG_PATH = '/content/drive/MyDrive/your_image.jpg'
\end{lstlisting}

\paragraph{Option B: Upload directly to Colab.}
Uncomment the upload line in the cell:
\begin{lstlisting}[language=Python]
from google.colab import files
up = files.upload()
IMG_PATH = list(up.keys())[0]
\end{lstlisting}

Run the cell. The output displays:
\begin{itemize}
    \item The predicted bug-bite category for both the Control and TC models.
    \item A probability bar chart for each of the five classes, for both
          pipelines side by side.
\end{itemize}

\subsubsection{Step 7: Generate Visual Explanations (Optional)}

\begin{description}
    \item[GradCAM (Section 8):] Highlights the image regions that most
          influenced the model's decision. Produces a $3 \times 2$ grid:
          one row per architecture (ConvNeXt-Tiny, DenseNet-121, InceptionV3),
          one column per pipeline (Control and TC).

    \item[LIME (Section 9):] Highlights image superpixels by their
          contribution to the prediction. Red regions support the predicted
          class; blue regions contradict it. This step takes approximately
          2--5 minutes on CPU.
\end{description}

\subsection{Retraining the Models}
\label{sec:mg-retrain}
% ============================================================

Retraining is only necessary when the dataset changes substantially, for
example when new bug-bite categories are added or when the existing labelled
data is significantly expanded. It is not required for routine operation.

\subsubsection{Hardware Requirements}

\textbf{A dedicated GPU is required for retraining.} The full training sweep
(63 configurations) was completed on an NVIDIA RTX A5000 (24\,GB VRAM) and
took approximately 100--130 hours of continuous GPU time. Google Colab free
tier is not sufficient for retraining; a Colab Pro instance with a high-RAM
GPU runtime, or equivalent dedicated hardware, is the minimum viable option
for partial retraining.

If only a single configuration needs to be retrained (rather than the full
sweep), the estimated runtime is 1.5--2 hours on equivalent hardware.

\subsubsection{Preparing the Cyclone Dataset}
\label{sec:mg-retrain-data}

The cyclone dataset is required for the TC pre-training stage. It can be
downloaded automatically from NOAA public servers using the provided script:

\begin{lstlisting}[language=bash]
# Full dataset: 4000 images per category (approximately 4 hours)
python miscellaneous_code/fetch_cyclone_dataset.py

# Quick test: 5 images per category
python miscellaneous_code/fetch_cyclone_dataset.py --trial
\end{lstlisting}

The download is resumable. If interrupted, re-run the same command and it
will continue from where it stopped. Total dataset size is approximately
20,000 images across five intensity categories.

Contact \texttt{ishay.yulzary@gmail.com} to request the pre-built dataset
split if you wish to avoid running the download.

\subsubsection{Configuring Dataset Paths}

Before running training, update the dataset paths in
\texttt{miscellaneous\_code/run\_experiments.py}:

\begin{lstlisting}[language=Python]
BUG_TRAIN = '/path/to/bug_data/train'
BUG_VAL   = '/path/to/bug_data/val'
TC_TRAIN  = '/path/to/cyclone_data_split/train'
TC_VAL    = '/path/to/cyclone_data_split/val'
\end{lstlisting}

\subsubsection{Running the Training Sweep}

\begin{lstlisting}[language=bash]
# Start or resume the full hyperparameter sweep
python miscellaneous_code/run_experiments.py

# Check progress at any time
python miscellaneous_code/run_experiments.py --status
\end{lstlisting}

\paragraph{Pausing and resuming.}
The sweep can be safely interrupted at any time:
\begin{itemize}
    \item Press \textbf{Ctrl-C}, or create the file \texttt{results/PAUSE},
          to stop the sweep after the current model finishes. All checkpoints
          are preserved.
    \item Re-run the same command to resume from where it stopped.
    \item If the process was killed unexpectedly (crash or power loss),
          re-running will automatically recover: partially-completed
          configurations restart from their last saved checkpoint.
\end{itemize}

\paragraph{Updating the weights archive.}
After retraining, the new weight files are located in
\texttt{results/checkpoints/}. To make them available to the inference
notebook, package the relevant checkpoint directories into a new
\texttt{project\_book\_results.tar} archive and upload it to Google Drive,
replacing the previous file.

For a local training environment, install dependencies with:

\begin{lstlisting}[language=bash]
pip install torch torchvision timm numpy Pillow opencv-python \
            scikit-learn matplotlib tqdm

# Optional XAI packages
pip install shap lime scikit-image dice-ml

# Cyclone dataset fetch
pip install netCDF4 requests pandas tqdm
\end{lstlisting}

There is no \texttt{requirements.txt} pinning specific versions for the
training environment. The project was developed and tested with
PyTorch 2.x and timm 0.9.x. If you encounter compatibility errors,
contact \texttt{ishay.yulzary@gmail.com} for the exact environment
specification used during the experiments.

\subsection{Troubleshooting}
\label{sec:mg-troubleshoot}
% ============================================================

\subsubsection{Drive mount or archive not found}

\textbf{Symptom:}
\begin{lstlisting}
PROJECT_ROOT exists: False
\end{lstlisting}
or
\begin{lstlisting}
Archive exists: False
\end{lstlisting}

\textbf{Resolution:}
\begin{enumerate}
    \item Verify that \texttt{project\_book\_results.tar} is present in
          \texttt{MyDrive/Capstone/} in your Google Drive.
    \item Check that you authorised Drive access when Colab prompted for it
          in Section 2. If you skipped the authorisation dialog, re-run the
          mount cell and complete the authorisation.
    \item If the \texttt{PROJECT\_ROOT} path in Section 2 does not match
          your Drive folder structure, update the value directly inside
          that cell in the notebook source and re-run it. Changing it in
          a separate cell is not sufficient, as subsequent cells reference
          the variable by name.
\end{enumerate}

\subsubsection{Model weights not found after extraction}

\textbf{Symptom:} Section 5 raises a \texttt{FileNotFoundError} when
loading model weights.

\textbf{Resolution:}
\begin{enumerate}
    \item Re-run Section 3 and confirm the extraction step completes
          without errors.
    \item In the cell output, verify that the listed \texttt{.pt} files
          match the expected names:
          \texttt{control\_convnext.pt}, \texttt{control\_densenet.pt},
          \texttt{control\_inception.pt},
          \\\texttt{tc\_bug\_convnext.pt}, \texttt{tc\_bug\_densenet.pt},
          \texttt{tc\_bug\_inception.pt}.
    \item If the archive structure differs from the expected layout, update
          the \texttt{CTRL\_SUBDIR} and \texttt{TC\_SUBDIR} variables in
          Section 5 to match the actual subdirectory names inside the archive.
\end{enumerate}

\subsubsection{GPU out-of-memory error during training}

\textbf{Symptom:} \texttt{torch.cuda.OutOfMemoryError} during
\texttt{run\_experiments.py}.

\textbf{Resolution:}
\begin{enumerate}
    \item Reduce the batch size for the affected architecture in the
          \texttt{MODELS} list in \texttt{run\_experiments.py}.
          The relevant columns are \texttt{cyc\_p1\_bs} (cyclone phase-1
          batch size) and \texttt{bug\_bs} (bug-bite batch size).
    \item For InceptionV3 in particular, the phase-1 batch size may need
          to be reduced to 64 or below on GPUs with less than 24\,GB VRAM.
    \item Re-run the sweep. Configurations that completed before the crash
          are not repeated.
\end{enumerate}

\subsubsection{NOAA download failures during cyclone dataset fetch}

\textbf{Symptom:} Repeated warnings such as
\begin{lstlisting}
! Index fetch failed for <year>: ...
\end{lstlisting}
or slow/incomplete downloads.

\textbf{Resolution:}
\begin{enumerate}
    \item Re-run the fetch script. Downloads are resumable; already-saved
          images are not re-downloaded.
    \item Reduce the worker count if the server rate-limits the connection:
\begin{lstlisting}[language=bash]
python miscellaneous_code/fetch_cyclone_dataset.py --workers 2
\end{lstlisting}
    \item If NOAA servers are temporarily unavailable, contact
          \texttt{ishay.yulzary@gmail.com} to obtain the pre-built dataset
          archive directly.
\end{enumerate}

\subsubsection{LIME cell runs for a very long time}

\textbf{Symptom:} Section 9 of the inference notebook appears to hang.

\textbf{Resolution:}
LIME generates 50 perturbed versions of the input image and runs each through
all six models. On a Colab CPU runtime this takes 2--5 minutes; this is
expected behaviour. Do not interrupt the cell. If the session times out,
re-run Sections 4 and 5 to reload the models, then re-run Section 9.

\subsubsection{Training sweep shows no progress after resuming}

\textbf{Symptom:} Re-running \texttt{run\_experiments.py} after an
interruption prints \texttt{All configs already completed} but results
appear incomplete.

\textbf{Resolution:}
\begin{enumerate}
    \item Run \texttt{python miscellaneous\_code/run\_experiments.py --status}
          to view the current state of each configuration.
    \item If all 63 configurations report \texttt{completed} but results
          are missing, the \\\texttt{results/experiment\_results.json} file
          may be corrupted or empty. Delete it and re-run; the sweep will
          re-evaluate all existing checkpoints without retraining.
    \item If fewer than 63 configurations are completed, the pending ones
          will resume automatically on the next run.
\end{enumerate}
